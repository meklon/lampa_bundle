# media-stack

Домашний медиа-стек: заказ фильма или сезона сериала с телефона через Lampa →
автоматический подбор релиза, загрузка, каноничное переименование, готовая
библиотека для Kodi.

## Что где

| Путь | Что |
|---|---|
| `CLAUDE.md` | Инварианты и запреты. Читать первым |
| `docs/SPEC.md` | Полная спецификация |
| `docs/PROCESS.md` | Этапы, стоп-условия, формат отчёта |
| `docs/ACCEPTANCE.md` | Критерии приёмки по этапам |
| `docs/NAMING.md` | Схема именования файлов |
| `docs/OPEN-QUESTIONS.md` | Непроверенные допущения |
| `openapi/` | Схемы API *arr — источник истины по именам полей |
| `provision/` | Конфигурация *arr скриптами через API |
| `scripts/` | Служебные скрипты |
| `fixtures/` | Тестовый стенд: локальный торрент |
| `checks/` | Проверки приёмки |
| `bridge/` | Мост Lampa → *arr |
| `reports/` | Отчёты по этапам |

## Первый запуск на чистой ВМ

```bash
cp .env.example .env
# заполнить .env: DATA_ROOT, теги образов, PUID/PGID

./scripts/init-data.sh            # раскладка /data и права
docker compose up -d              # поднять стек
# забрать API-ключи из веб-морд, дописать в .env
docker compose up -d              # перезапустить bridge с ключами

./scripts/fetch-openapi.sh        # схемы API в openapi/
./scripts/check-versions.sh       # сверка схем с живыми инстансами

./provision/provision.sh          # конфигурация *arr
./fixtures/make-fixture.sh        # тестовый торрент

./checks/01-containers.sh
./checks/02-data-layout.sh
# … далее по docs/ACCEPTANCE.md
```

## Важное в двух строках

**Единственное монтирование `/data`.** Раздельные монтирования ломают жёсткие
ссылки, и *arr молча копирует вместо связывания. Место уходит вдвое,
ошибки нет. Проверяется в `checks/02` и `checks/04`.

**Трекеры подключаются последними, руками.** Вся разработка идёт на локальном
торренте из `fixtures/`.

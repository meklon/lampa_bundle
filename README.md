# media-stack

Домашний медиа-стек: заказ фильма или сезона сериала с телефона через Lampa →
автоматический подбор релиза, загрузка, каноничное переименование, готовая
библиотека для Kodi.

## Установка

```bash
cp .env.example .env
# заполнить: пути, теги образов, ключи, TMDB_TOKEN, CORS_ORIGINS

docker compose up -d --build
```

Одна команда. Стек сам создаёт каталоги, проверяет жёсткие ссылки, задаёт
пароль qBittorrent и приводит конфигурацию *arr к описанной в репозитории.

Проверить:

```bash
./checks/01-containers.sh
./checks/02-data-layout.sh
```

`--build` нужен, чтобы пересобрался bridge: `compose up` без него берёт
существующий образ и не замечает изменений в исходниках.

### Что заполняется руками

**Пути.** `DATA_ROOT` — единственное монтирование, оно становится `/data` во
всех контейнерах. Остальное задаётся **относительно** него:

```
DATA_ROOT=/mnt/ssd_storage/video

TORRENTS_PATH=torrents        # промежуточное хранение
MOVIES_PATH=media/movies      # фильмы
TV_PATH=media/tv              # сериалы
```

Можно указать на существующие каталоги, например `MOVIES_PATH=Movies` и
`TV_PATH=TV shows`.

**Оставаться внутри `DATA_ROOT` обязательно.** Раздельные bind-монтирования
ломают жёсткие ссылки даже когда обе точки лежат на одной файловой системе:
проверено, `link()` возвращает `EXDEV` при совпадающем номере устройства.
Отсюда следствие — сравнения `stat -c %d` недостаточно, решает проба настоящей
ссылкой. Она делается при каждом запуске и **валит развёртывание**, если
ссылка не создалась.

**Ключи API** — придумываете сами, например `openssl rand -hex 16`. Они
передаются сервисам переменными окружения, никаких файлов заранее готовить не
нужно.

**Пароль qBittorrent** — тоже ваш. Стек посчитает из него хеш и положит в
конфиг до первого старта.

**Теги образов** — конкретные версии, не `latest`: миграции БД у *arr
односторонние.

**`TMDB_TOKEN`** — Bearer-токен v4 (Read Access Token), не v3 `api_key`.
Первый длинный и начинается с `eyJ`, второй — 32 символа hex.

**`CORS_ORIGINS`** — адрес **страницы** Lampa (обычно Lampac на `:9118`), а не
адрес bridge. Никогда `*`.

### Как это устроено

Три сервиса compose делают всю подготовку:

| Сервис | Когда | Что делает |
|---|---|---|
| `init` | до старта остальных | каталоги, проба жёсткой ссылки, пароль qBittorrent |
| остальные | по готовности `init` | поднимаются с ключами из окружения |
| `provision` | по готовности *arr | категории, root folders, клиент загрузки, схема имён |

`provision` идемпотентен и запускается при каждом `up`: ручные правки через
веб-морды возвращаются к описанному в репозитории.

## Подключение с телефона

Стек публикует порты на всех интерфейсах, поэтому всё доступно по адресу ВМ
в локальной сети.

```
Lampa (Lampac)   http://<адрес-вм>:9118      ← сюда заходить с телефона
плагин           http://<адрес-вм>:8000/plugin.js
```

1. Открыть Lampa по адресу Lampac либо направить туда приложение на телефоне.
2. **Настройки (шестерёнка) → Расширения → добавить плагин**, указать адрес
   `http://<адрес-вм>:8000/plugin.js`.
3. Открыть карточку фильма — в ряду кнопок появится «Заказать».
   Плагин спросит качество; для сериала сначала сезон, потом качество.

Качество — это **профиль** Radarr/Sonarr, а не просто разрешение: он задаёт и
что скачать, и до чего потом апгрейдить. Список приходит из самих *arr, первым
идёт умолчание из `.env`. Заводить и переименовывать профили — в веб-мордах
Radarr и Sonarr, плагин подхватит новые сам.

Адрес bridge плагин выводит **сам** из адреса, по которому его установили:
поставили с `:8000` — заказы уйдут туда же. Настраивать нечего.

Если заказ не уходит, смотреть логи: bridge пишет каждый входящий запрос
вместе с заголовком `origin`.

```bash
docker compose logs -f bridge
```

Увидели в логе origin, которого нет в `CORS_ORIGINS`, — дописать его туда и
`docker compose up -d bridge`. У приложения на телефоне origin может
отличаться от адреса Lampac вплоть до `null`.

## Что ещё нужно сделать руками

Автоматизировать это нельзя или намеренно не стали:

| Шаг | Почему руками |
|---|---|
| Индексаторы в Prowlarr | логины к приватным трекерам; и они добавляются **последними**, когда конвейер уже зелёный |
| `BRIDGE_ENV=prod` | до этого поиск не запускается никогда — защита отладочного цикла от реальных загрузок |
| Проверка плагина в живой Lampa | интерфейс и пульт, автоматизации не поддаётся |
| Уведомления на Health Issue | нужен токен Telegram или адрес ntfy |
| Подключение Kodi | вне скоупа, схема имён под него уже зафиксирована |

Порядок именно такой: сначала плагин в dev-режиме (безопасно), потом
индексаторы, и только потом `prod` — на одном фильме, под наблюдением.

## Важное в двух строках

**Единственное монтирование `/data`.** Раздельные монтирования ломают жёсткие
ссылки, и *arr молча копирует вместо связывания. Место уходит вдвое,
ошибки нет. Проверяется в `checks/02` и `checks/04`.

**Трекеры подключаются последними, руками.** Вся разработка идёт на локальном
торренте из `fixtures/`.

## Порты

| Сервис | Порт | Кому нужен |
|---|---|---|
| Lampac | 9118 | телефону: каталог и фронтенд Lampa |
| bridge | 8000 | телефону: плагин и приём заказов |
| qBittorrent | 8081 | вам |
| Radarr | 7878 | вам |
| Sonarr | 8989 | вам |
| Prowlarr | 9696 | вам |
| Kodi (на хосте, вне compose) | 8080 | вне скоупа |

qBittorrent переназначен с 8080 на 8081: по умолчанию конфликтует с Kodi.

# media-stack

Домашний медиа-стек: заказ фильма или сезона сериала с телефона через Lampa →
автоматический подбор релиза, загрузка, каноничное переименование, готовая
библиотека для Kodi.

## Установка

Нужны **два файла**: `docker-compose.yml` и `.env`. Ни репозитория, ни
исходников, ни сборки на сервере.

```bash
mkdir -p /opt/media-stack && cd /opt/media-stack
curl -O https://raw.githubusercontent.com/meklon/lampa_bundle/v1.0.1/docker-compose.yml
curl -o .env https://raw.githubusercontent.com/meklon/lampa_bundle/v1.0.1/.env.example
# заполнить .env
docker compose up -d
```

Стек сам создаёт каталоги, проверяет жёсткие ссылки, задаёт пароль
qBittorrent, пишет конфигурацию Lampac и приводит настройки *arr к
описанным. Проверено начисто: из каталога с двумя файлами весь стек
поднимается за 13 секунд.

Для Ansible это три задачи:

```yaml
- template: src=docker-compose.yml  dest=/opt/media-stack/docker-compose.yml
- template: src=env.j2              dest=/opt/media-stack/.env
- community.docker.docker_compose_v2: project_src=/opt/media-stack
```

### Что заполняется в .env

```
DATA_ROOT=/mnt/ssd_storage/video   # единственное монтирование -> /data
TORRENTS_PATH=torrents             # промежуточное хранение
MOVIES_PATH=media/movies           # фильмы
TV_PATH=media/tv                   # сериалы
CONFIG_ROOT=./config               # конфигурация сервисов

PUID/PGID/UMASK/TZ                 # владелец данных
RADARR_API_KEY, SONARR_API_KEY, PROWLARR_API_KEY    # openssl rand -hex 16
QBITTORRENT_USER, QBITTORRENT_PASSWORD              # придумываете сами
TMDB_TOKEN                         # Bearer v4, не v3 api_key
```

Остальное имеет проверенные умолчания и обычно не трогается: версии образов,
схема имён, `CORS_ORIGINS`.

**Пути обязаны оставаться внутри `DATA_ROOT`.** Раздельные bind-монтирования
ломают жёсткие ссылки даже на одной файловой системе — проверено, `link()`
возвращает `EXDEV` при совпадающем номере устройства. Проба настоящей ссылкой
делается при каждом запуске и **валит развёртывание**, если не сработала.

### Что можно переопределить

| Переменная | Умолчание |
|---|---|
| `RADARR_TAG`, `SONARR_TAG`, `PROWLARR_TAG`, `QBITTORRENT_TAG`, `LAMPAC_TAG` | проверенные версии в compose |
| `RADARR_MOVIE_FORMAT`, `SONARR_EPISODE_FORMAT` и остальные пять | строки TRaSH Guides из образа |
| `CORS_ORIGINS` | пусто = «тот же хост, любой порт» |
| `STACK_IMAGE`, `BRIDGE_IMAGE` | опубликованные образы |

`STACK_VERSION` в `.env.example` задан явно и указывает на текущий выпуск.
Без него взялся бы `latest`, и две установки, сделанные в разные дни, были бы
разными.

Смена версий *arr — правка `docker-compose.yml`, а не `.env`: миграции БД
у них односторонние, и такое решение должно проходить через git и снапшот.

Схему имён менять **до** наполнения библиотеки, иначе переименовывать всё
разом.

### Разработка

```bash
git clone <репозиторий> && cd lampa_bundle
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

Наложение собирает образы из исходников вместо опубликованных.

## Подключение с телефона

Стек публикует порты на всех интерфейсах, поэтому всё доступно по адресу ВМ
в локальной сети.

```
Lampa (Lampac)   http://<адрес-вм>:9118      ← сюда заходить с телефона
плагин           http://<адрес-вм>:8000/plugin.js
```

1. Открыть Lampa по адресу Lampac либо направить туда приложение на телефоне.
2. **Настройки (шестерёнка) → Расширения → добавить плагин**, указать адрес
   `http://<адрес-вм>:8000/plugin.js`.
3. Открыть карточку фильма — в ряду кнопок появится «Заказать».
   Плагин спросит качество; для сериала сначала сезон, потом качество.
4. Если заказ уже сделан, вместо кнопки в карточке видно его текущее
   состояние («Закачивается 44%», «В библиотеке» и так далее) с пунктом
   «Обновить» рядом — перечитать состояние без выхода из карточки.

Качество — это **профиль** Radarr/Sonarr, а не просто разрешение: он задаёт и
что скачать, и до чего потом апгрейдить. Список приходит из самих *arr, первым
идёт умолчание из `.env`. Заводить и переименовывать профили — в веб-мордах
Radarr и Sonarr, плагин подхватит новые сам.

Адрес bridge плагин выводит **сам** из адреса, по которому его установили:
поставили с `:8000` — заказы уйдут туда же. Настраивать нечего.

Если заказ не уходит, смотреть логи: bridge пишет каждый входящий запрос
вместе с заголовком `origin`.

```bash
docker compose logs -f bridge
```

Обычно настраивать нечего. Но если в логе виден origin, не подпадающий под
правило «тот же хост» — например `null` у упакованного приложения, — дописать
его в `CORS_ORIGINS` и `docker compose up -d bridge`.

## Что ещё нужно сделать руками

Автоматизировать это нельзя или намеренно не стали:

| Шаг | Почему руками |
|---|---|
| Индексаторы в Prowlarr | логины к приватным трекерам; и они добавляются **последними**, когда конвейер уже зелёный |
| `BRIDGE_ENV=prod` | до этого поиск не запускается никогда — защита отладочного цикла от реальных загрузок |
| Проверка плагина в живой Lampa | интерфейс и пульт, автоматизации не поддаётся |
| Уведомления на Health Issue | нужен токен Telegram или адрес ntfy |
| Подключение Kodi | вне скоупа, схема имён под него уже зафиксирована |

Порядок именно такой: сначала плагин в dev-режиме (безопасно), потом
индексаторы, и только потом `prod` — на одном фильме, под наблюдением.

## Важное в двух строках

**Единственное монтирование `/data`.** Раздельные монтирования ломают жёсткие
ссылки, и *arr молча копирует вместо связывания. Место уходит вдвое,
ошибки нет. Проверяется в `checks/02` и `checks/04`.

**Трекеры подключаются последними, руками.** Вся разработка идёт на локальном
торренте из `fixtures/`.

## Порты

| Сервис | Порт | Кому нужен |
|---|---|---|
| Lampac | 9118 | телефону: каталог и фронтенд Lampa |
| bridge | 8000 | телефону: плагин и приём заказов |
| qBittorrent | 8081 | вам |
| Radarr | 7878 | вам |
| Sonarr | 8989 | вам |
| Prowlarr | 9696 | вам |
| Kodi (на хосте, вне compose) | 8080 | вне скоупа |

qBittorrent переназначен с 8080 на 8081: по умолчанию конфликтует с Kodi.

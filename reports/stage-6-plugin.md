## Что сделано

**`bridge/static/plugin.js`** — реализован целиком. Кнопка «Заказать» в
карточке, выбор сезона для сериала, один POST на `/order`, уведомление с
текстом `detail` из ответа.

Плагин остался тонким: ни ретраев, ни хранения, ни опроса статуса, ни знания
об *arr.

**`bridge/tests/plugin_harness.js`** — стенд на node: подставляет заглушки
вместо Lampa, jQuery и DOM, скармливает плагину событие `full` с **записанными
данными TMDB** и смотрит, что получилось.

**`bridge/tests/test_plugin.py`** — запускает стенд из общего прогона pytest,
плюс проверяет синтаксис и отсутствие секретов.

## Решения, которые пришлось принять

### Адрес bridge выводится из адреса самого плагина

В заготовке стояло `var BRIDGE = ''` с комментарием «тот же origin, CORS не
возникает». Для production это верно, для отладки — нет: плагин исполняется в
странице Lampa, и относительный `fetch('/order')` ушёл бы на origin Lampa
(`localhost:3000`), а не bridge (`:8000`). Промах был бы молчаливым.

Адрес берётся из `document.currentScript.src` — из того адреса, по которому
браузер загрузил плагин. Хардкода нет, настраивать нечего, секрет не
появляется.

### Запасной якорь для кнопки

Образец в `online.js` цепляет кнопку после `.view--torrent`. Но эта кнопка
скрывается, когда торренты выключены в настройках
(`full/start.js:81`). Поэтому: если якорь есть — после него, иначе в конец
`.full-start-new__buttons`. Проверено стендом отдельным случаем.

### Защита от повторной вставки

`complite` приходит и при возврате в карточку, а не только при первом
открытии. Без проверки кнопок накопилось бы несколько. Плагин проверяет
`.view--order` перед вставкой.

### Сезон 0

TMDB отдаёт спецвыпуски как сезон 0, и `bridge` его принимает — номер
валидный, `OrderRequest.season` допускает `ge=0`. В списке он подписан
«Спецвыпуски», а не «Сезон 0».

## Чего проверка НЕ доказывает

Стенд подставляет заглушки вместо Lampa, jQuery и DOM. **Заглушка всегда ведёт
себя так, как её написал автор** — то есть она подтверждает мои же
представления об API, а не работу в настоящей Lampa. Это ровно та ошибка, от
которой предостерегает `bridge/tests/README.md` про моки, написанные из
головы; здесь она неустранима без живого интерфейса.

Не проверено:

- кнопка **видна** в карточке и встала в нужное место
- фокус переходит на неё **пультом**, а не только мышью
- список сезонов выглядит и листается как надо
- после выбора фокус возвращается в карточку, а не теряется
- уведомление реально показывается поверх интерфейса

`docs/ACCEPTANCE.md` этот этап и описывает как ручной: «проверяется вручную,
автоматизации не поддаётся». Так и есть.

### Попытка поднять живую Lampa — чем закончилась

Пробовал довести до настоящей проверки, а не остановиться на заглушках:

- `npm install` в `yumata/lampa-source` прошёл (561 пакет)
- `npm run doc` собрался, `build/doc/index.html` получен. **Документация
  покрывает только функции с JSDoc** — `Select.show` там есть, а событий
  `full` и структуры `data.movie` нет. Поэтому чтение исходников было не
  перестраховкой, а необходимостью
- `npx gulp pack_github` упал: `ENOENT ./dest/app.js` — сборка бандла идёт
  отдельным шагом
- `npx gulp` (задача по умолчанию) поднял browser-sync на `:3000`, но это
  только watcher: `build/web/` не создаётся, пока не изменится файл в `src/`,
  и приложение по `/` отдаёт 404

Дальше копать смысла не было: **браузера в ВМ нет**, поэтому даже полностью
собранная Lampa не дала бы визуальной проверки. Ни `jsdom`, ни `puppeteer`,
ни chromium в системе не установлены.

Процессы остановлены, стек проекта не задет.

## Что нужно от человека

Прогнать ручную проверку по `ACCEPTANCE.md`, этап 6:

```bash
# 1. Локальная Lampa
cd yumata/lampa-source && npm install && npm run start   # localhost:3000

# 2. В интерфейсе: Настройки -> Расширения -> добавить плагин
#    http://<адрес-вм>:8000/plugin.js

# 3. Открыть карточку фильма, затем карточку сериала

# 4. Смотреть, что пришло в bridge
docker compose logs -f bridge
```

Ожидаемое в логах при нажатии — строка вида

```
-> POST /order body={"tmdb_id":10378,"type":"movie","season":null}
```

с **правильным** `tmdb_id` и типом. Если `tmdb_id` окажется чужим или тип
перепутан — это расхождение с тем, что я прочитал в исходниках, и его надо
разбирать, а не подгонять.

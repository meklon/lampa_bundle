## Открытый вопрос №1 закрыт опытом

Схема на этапе 4 подтвердила форму, но не поведение. Проверено на живом
Sonarr 4.0.19.2979.

**Один POST не работает.** Отправлено `seasons: [{1, monitored: true}]`
вместе с `addOptions.monitor: "none"`:

```
ответ POST : {"seasons":[{"seasonNumber":1,"monitored":true}]}
в базе     : {"seasons":[{"seasonNumber":1,"monitored":false}]}
```

`addOptions.monitor` затирает флаги после добавления, **а ответ POST этого не
показывает**. Проверка результата по телу ответа дала бы ложноположительный
результат.

**`monitoringOptions` в seasonpass — тот же капкан.** Сериал с шестью
сезонами, просили один:

| `monitoringOptions` | Сезонов под мониторингом стало |
|---|---|
| `{"monitor": "none"}` | 0 |
| `{"monitor": "skip"}` | 0 |
| объект не передан | 1 — ровно запрошенный |

Работающая альтернатива `PUT /api/v3/series/{id}` с изменённым массивом
`seasons` тоже проверена и работает. Выбран `seasonpass`: не требует
пересылать объект сериала целиком.

Перенесено в `SPEC.md` 2.5, пункт из `OPEN-QUESTIONS.md` удалён.

## Гипотезы, которые НЕ подтвердились

### `title` обязателен, хотя схема помечает его необязательным

Самая дорогая находка этапа. В `MovieResource` у `title` стоит
`"nullable": true`, списка `required` у схемы нет вовсе. Реальность:

```
Radarr: 500 System.NullReferenceException
          at NzbDrone.Core.Organizer.FileNameBuilder.CleanTitle(String title)
Sonarr: 500 System.ArgumentNullException: Value cannot be null (Parameter 'input')
          at System.Text.RegularExpressions...
```

Оба строят путь папки **в момент добавления** — по `movieFolderFormat` и
`seriesFolderFormat`, где стоят токены названия. Пустое название даёт
исключение внутри приложения, а не понятную ошибку валидации.

**Схема — источник истины по именам полей, но не по обязательности.** Это
второй такой случай после `colonReplacementFormat` на этапе 4.

Название берётся у самих *arr: `movie/lookup/tmdb?tmdbId=` и
`series/lookup?term=tvdb:`. Не у TMDB — для переводных тайтлов строки
расходятся, и папка создалась бы под одним именем, а канонической считалась бы
другая. Оба вызова — поиск по идентификатору, а не по названию; запрет из
`CLAUDE.md` касается нечёткого `term=<название>`.

### Тестовые заказы шли бы в настоящую библиотеку

`checks/05-bridge-movie.sh` сверяет `rootFolderPath` фильма с
`TEST_RADARR_ROOT`, а `docker-compose.yml` эту переменную в bridge **не
передавал**, и в конфигурации её не было вовсе. Bridge складывал бы отладочные
заказы в боевой каталог — прямо против `CLAUDE.md`.

Добавлены `test_radarr_root` / `test_sonarr_root` и свойства
`radarr_root_effective` / `sonarr_root_effective`, возвращающие тестовый
каталог в dev-режиме. Переменные проброшены в compose. Тестовые заказы заодно
помечаются тегом из `TEST_TAG` — чтобы потом снести не глядя.

### `pip install -e .` в контейнере не работал, и это было не видно

`pyproject.toml` не указывал пакет, и setuptools отказывался угадывать:
`Multiple top-level packages discovered in a flat-layout: ['app', 'static']`.

Ошибка не проявлялась, потому что `Dockerfile` содержал

```
RUN pip install --no-cache-dir -e . 2>/dev/null || pip install --no-cache-dir \
      "fastapi>=0.115" "uvicorn[standard]>=0.32" ...
```

— то есть глушил вывод и молча ставил второй, захардкоженный список версий.
Сборка проходила, `pyproject.toml` не участвовал вовсе, а два списка
зависимостей могли разъезжаться сколько угодно.

Исправлено: в `pyproject.toml` добавлено `[tool.setuptools] packages = ["app"]`,
из `Dockerfile` убран запасной вариант. Сломанная сборка обязана падать, а не
подменяться.

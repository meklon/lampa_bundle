## Как разрешался tmdb_id без токена TMDB

Скрипт требовал `TMDB_TOKEN` жёстко и падал без него. Токена пока нет, а
хардкодить идентификатор запрещено прямо в `CLAUDE.md`.

Добавлен запасной путь: собственный лукап Radarr
`GET /api/v3/movie/lookup?term=`. Radarr ходит в метаданные сам, нашего токена
не требует. Основным остаётся TMDB — как только токен появится, скрипт снова
пойдёт туда.

**Это соседствует с запрещённой подменой, поэтому ограничено явно.** В таблице
`CLAUDE.md` запрещено «искать по названию в Sonarr (`series/lookup?term=`)»
вместо трансляции TMDB→TVDB. Разница:

- запрет касается **bridge**, где нечёткое совпадение притащит не тот тайтл, и
  никто не заметит;
- здесь — **стенд**, и результат сверяется с `catalog.yml` по названию **и**
  году, причём требуется **ровно один** кандидат. При двух и более скрипт
  отказывается работать и печатает всех, а не берёт первого попавшегося.

Проверка сработала на живых данных: по запросу «Big Buck Bunny» Radarr вернул
двух кандидатов — `10378` (2008) и `1627969` (год 0). Фильтр по году оставил
одного.

В bridge этот путь не появится: там только точный `tvdbId`.

## Второй пробел: фильм никто не добавлял в Radarr

`make-fixture.sh` раскладывал данные и добавлял торрент, но фильм в библиотеку
Radarr не заводил. Импортировать было бы не во что: Radarr сопоставляет
завершённую загрузку с фильмом из своей библиотеки, а не создаёт его сам.

Добавлен шаг `POST /api/v3/movie`. Шаблон объекта берётся из
`GET /api/v3/movie/lookup/tmdb?tmdbId=…` — то есть от самого Radarr, а не
собирается руками: состав `MovieResource` по памяти не воспроизводится.

Параметры: `TEST_RADARR_ROOT`, профиль из `RADARR_PROFILE`, тег из `TEST_TAG`,
`addOptions.searchForMovie: false`.

Это **не** отменяет пробел в `bridge/app/radarr.py`: там payload по-прежнему
собирается из схемы `openapi/` на этапе 5. Разные пути, разные требования.

## Гипотезы, которые подтвердились

**Схема имён из `NAMING.md` применяется буквально.** Фактический хвост
`[WEBDL-1080p][MP3 2.0][x264]-TEST` разобран по токенам в `docs/NAMING.md` и
занесён туда как эталон. Пустые токены (`{{Edition Tags}}`, `{[Custom
Formats]}`, `{[MediaInfo VideoDynamicRangeType]}`) схлопываются вместе со
скобками — это норма.

**Локальный торрент проверяется как завершённый сразу.** Данные лежали на
месте до добавления, qBittorrent показал `progress=1` без сети.

**Импорт сработал без вмешательства.** После `RefreshMonitoredDownloads`
`hasFile` стал `true` с первой попытки, очередь пуста.

## Гипотезы, которые НЕ подтвердились

### Radarr берёт первую аудиодорожку, а не лучшую

В файле две дорожки: mp3 2.0 и ac3 5.1. `audioStreamCount` Radarr видит равным
2, но в имя пошло `[MP3 2.0]` — первая по порядку, не самая качественная.

На настоящих релизах это обычно одно и то же, но эталон в `NAMING.md`
привязан к конкретному материалу: сменится короткометражка — хвост
изменится, и ожидание придётся переснять. Записано там же.

### `du` на одном дереве не показывает экономию

Ожидалось, что `du` посчитает данные дважды. На деле `du` схлопывает жёсткие
ссылки в пределах **одного вызова**: оба каталога в одной команде дали 264 МБ,
а не 528 МБ. Удвоение видно, только если вызывать `du` на каждом дереве
отдельно. Формулировка в `SPEC.md` 1.7 («`du` считает такие данные дважды»)
верна лишь для раздельных вызовов.

## Дополнение: сериальная часть стенда

Собрана после того, как появился токен TMDB.

**Материал.** Breaking Bad — разрешён через TMDB, не по памяти:
`/search/tv?query=Breaking Bad&first_air_date_year=2008` дал ровно одного
кандидата, `/tv/1396/external_ids` → `tvdb_id=81189`. Статус `Ended`, поэтому
краевой случай с дописыванием эпизодов в идущий сезон (открытый вопрос №2)
сюда не примешивается.

Файлом положена та же короткометражка под именем
`Breaking.Bad.S01E01.1080p.WEB-DL.x264-TEST.mp4`. Sonarr сопоставляет по
имени, а не по содержимому.

**`make-fixture.sh series`** — новая ветка скрипта. Перевод TMDB→TVDB делается
заново через TMDB, а не берётся из `catalog.yml`: там `tvdb_id` лежит
справочно. Без токена ветка отказывается работать с явным объяснением —
лукап Radarr здесь не заменяет, Sonarr работает по TVDB.

Шаблон объекта берётся из `series/lookup?term=tvdb:81189`. Это **не**
запрещённый поиск по названию: `tvdb_id` уже получен от TMDB, а lookup только
отдаёт форму. Требуется ровно один кандидат.

Заданы два поля, чьи умолчания противоречат замыслу:
`monitorNewItems: "none"` (по умолчанию `"all"` — заказ сезона превратился бы
в подписку) и `seasonFolder: true` (по умолчанию `false`).

**Результат:**


## Дефект в самой проверке 04-hardlink.sh

Обнаружен, когда файлов стало два: проверка отчиталась зелёным, разобрав
**один** файл из двух.

Причина — `docker compose exec` внутри `while read`. Exec читает стандартный
ввод и съедает оставшиеся строки, которые цикл ещё не прочитал. Воспроизводится
на трёх строках:

```
printf 'a\nb\nc\n' | while IFS= read -r x; do
  echo "итерация: $x"; docker compose exec -T radarr true
done
→ итерация: a          # и всё
```

С `</dev/null` печатаются все три.

Это худший сорт поломки для этого проекта: **проверка, которая молча проверяет
не всё и отчитывается «прошло»**. Окажись второй файл копией вместо жёсткой
ссылки, `04-hardlink.sh` этого бы не заметила.

Исправлено: `</dev/null` каждому exec, ввод подаётся здесь-документом вместо
конвейера (конвейер уводил тело цикла в подоболочку, откуда `FAILED` не
возвращался наружу), и добавлена страховка — если проверено файлов меньше, чем
найдено, проверка падает.

Тот же приём есть в `provision/30-radarr.sh` и `40-sonarr.sh`, но там внутри
цикла `curl`, который stdin не читает: все пять writer'ов обрабатывались и
раньше. Плюс `set -euo pipefail` не даст ошибке в подоболочке пройти
незамеченной. Оставлено как есть.

## Открытые вопросы

**`checks/07-pipeline.sh` покрывает только фильмы.** Она смотрит категорию
`radarr` в qBittorrent и один ожидаемый путь аргументом. Сериальный эпизод
проверяется `04-hardlink.sh` и сверкой пути с `docs/NAMING.md` вручную.

её и не предполагалось, сериальная сторона закрывается
`06-bridge-season.sh` на этапе 5.

**Мониторинг сезонов у тестового сериала не настраивался.** Стенд добавляет
сериал и проверяет импорт; выбор конкретного сезона через `seasonpass` — работа
bridge и предмет открытого вопроса №1. Импорт эпизода при этом состоялся,
то есть для импорта мониторинг не требуется.

**Материал остаётся на диске.** 264 МБ в `fixtures/data/` и столько же
инодами в `torrents/` и `media/_test_movies/`. В git не попадает
(`.gitignore`), воссоздаётся `make-fixture.sh`. Тестовый root folder
выбрасывается целиком.

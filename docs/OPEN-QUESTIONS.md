# Блокирующие

## 1. Схема добавления сезона в Sonarr — какой из двух путей

**Что известно точно:**
- поле `monitorNewItems` существует, значения `all` и `none`, это API-форма
  настройки «Monitor New Seasons»; `none` предотвращает автоматический
  мониторинг новых сезонов
- эндпоинт `POST /api/v3/seasonpass` существует и задаёт мониторинг сезонов
  пачкой: массив `series` с `id`, `monitored` и вложенным `seasons`, плюс
  объект `monitoringOptions`
- значение `none` для `addOptions.monitor` допустимо
- массив `seasons` формально входит в состав данных добавления сериала

**Что неизвестно:** можно ли обойтись одним POST с массивом `seasons`, или
`addOptions.monitor` переопределит флаги в момент добавления, и нужен
второй шаг через `seasonpass`.

**Как проверить:** посмотреть `openapi/sonarr-v3-*.json`, схемы
`SeriesResource` и `AddSeriesOptions`. Затем добавить сериал через веб-морду
с выбором одного сезона и посмотреть в логах Sonarr, какой запрос ушёл.

**Что принято в `SPEC.md` до проверки:** двухшаговый путь как более надёжный.

**Влияние:** количество вызовов. На архитектуру не влияет.

## 2. Поведение `monitorNewItems` на идущих сериалах

**Что известно:** глобального значения по умолчанию для `monitorNewItems` нет,
задаётся только на сериал. Есть краевая проблема: эпизоды, дописанные позже
в уже отслеживаемый текущий сезон, могут оказаться немониторимыми.

**Что проверить:** заказать сезон **идущего** сериала и посмотреть, что
происходит с новыми эпизодами этого сезона и с началом следующего.

**Почему важно:** пользователь заказывает сезон, а не подписку на сериал.
Обратная ошибка — эпизод вышел, а Sonarr его не взял — тоже нежелательна.

**Стоп-условие №6** при обнаружении незаказанного мониторинга.

## 3. Точный состав полей `POST /api/v3/movie`

**Допущение:** `tmdbId`, `qualityProfileId`, `rootFolderPath`, `monitored`,
`minimumAvailability`, `addOptions.searchForMovie` достаточны и корректны.

**Что известно точно:** формально обязательным по схеме является только
`title`; практически добавление требует `tmdbId`, `qualityProfileId` и
`rootFolderPath`. Значения `minimumAvailability`: `announced`, `inCinemas`,
`released`, `preDB`, причём `preDB` сейчас идентичен `released`.

**Как проверить:** `openapi/radarr-v3-*.json`, схема `MovieResource` и
`AddMovieOptions`. Затем заказать фильм и убедиться, что задача поиска
реально появилась в Activity (в prod-режиме).

## 4. Как плагин Lampa получает `tmdb_id` и тип контента

**Что известно:** идентификаторы разрешаются асинхронно, с задержкой,
особенно когда основной источник — TMDB, а не CUB. Читать сразу при открытии
карточки нельзя, нужно дождаться полной загрузки. Рабочий основной источник —
TMDB; CUB не поддерживается. Lampa под лицензией ISC.

**Что неизвестно:** конкретный механизм — какое событие слушать, какой объект
опрашивать, где лежит тип контента, как правильно добавить кнопку в карточку.

**Как проверить:**
- собрать документацию локально: `npm run doc` в `yumata/lampa-source`,
  открыть `build/doc/index.html`
- прочитать рабочий плагин с исходниками: `and7ey/lampa`
- поднять `npm run start` и смотреть в консоли браузера

**Не искать в интернете** — там только каталоги плагинов, внутренностей нет.

**Замечание:** создание issue в `lampa-source` закрыто. Вопросы по
внутренностям — в Telegram-каналы проекта.

**Допущение:** Jackett-совместимый эндпоинт Prowlarr подходит под то, что
ожидает парсер Lampa, и один набор трекеров может обслуживать и *arr, и Lampa.

**Не проверялось.**

**Резервный путь:** JacRed для Lampa, Prowlarr для *arr. Два независимых
набора трекеров — некрасиво, но работает.

**Влияние:** только на второй поток (одноразовый просмотр). Основную цепочку
не задевает.

## 6. Категории qBittorrent в LME Torrent Manager

**Вопрос:** поддерживает ли плагин `torrentmanager.js` выбор категории или
каталога сохранения для конкретной загрузки в qBittorrent.

**Зачем:** если да — появляется альтернативный путь без bridge для части
сценариев. Скорее всего не нужен, но остаётся как факт для полноты.

**Как проверить:** посмотреть исходник `torrentmanager.js` на наличие полей
`category` или `savepath`, либо протестировать против живого qBittorrent.

**Влияние на текущую архитектуру:** нулевое. Выбор релиза руками из скоупа
исключён, заказ идёт через *arr.

## 7. Направление синхронизации Trakt-плагина Lampa

# Закрытые

Оставлено для истории, чтобы не проверять повторно.

- **Sonarr требует `tvdbId`, добавление по `tmdbId` не поддерживается.**
  Подтверждено. Трансляция через TMDB `/tv/{id}/external_ids` обязательна.
  Часть регионального контента `tvdb_id` не имеет.
- **Мониторинг одного сезона без будущих — возможно.** Через
  `monitorNewItems: "none"`. Прежнее ограничение снято.
- **Схемы OpenAPI не отдаются живым инстансом** по `/api/v3/openapi.json` на
  production-сборках; Swagger UI только в debug-режиме. Брать из исходников
  проектов.
- **Раздельные монтирования ломают жёсткие ссылки.** Подтверждено, это
  каноничная рекомендация TRaSH Guides.
- **`UMASK_SET` устарела**, использовать `UMASK`.
- **`VideoLibrary.Scan` с `directory` сломан для сериалов** начиная с Kodi
  v21 Omega. Для фильмов работает. Вне скоупа, но учтено в `SPEC.md`.
- **Лицензия Lampa** — ISC. Вопрос признан неважным, закрыт.

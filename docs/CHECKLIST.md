# CHECKLIST.md

Состояние работ. Единственное место, где написано, что уже сделано и что
осталось.

Пункт отмечается сделанным **только после того, как прошла проверка, которая
стоит рядом с ним**. «Код написан» и «работает» — разные утверждения;
отмечается второе.

---

## Как ведётся трекинг

Три уровня, каждый про своё, не дублируют друг друга:

| Где | Что там | Живёт |
|---|---|---|
| `docs/CHECKLIST.md` | состояние этапов и что чем доказано | между сессиями, в git |
| `reports/stage-N-*.md` | находки, точные запросы и ответы, сработавшие стоп-условия | между сессиями, в git |
| список задач агента | текущие шаги внутри сессии | до конца сессии |

Правило: если факт понадобится завтра — он идёт в `CHECKLIST.md` или в
`reports/`. Список задач агента исчезает вместе с сессией, полагаться на него
нельзя.

Подтверждённая или опровергнутая гипотеза дополнительно переносится в
`OPEN-QUESTIONS.md` по правилу из `PROCESS.md` раздел 6.

## Этап 9 — прослеживаемость

Ветка `stage/9-traceability`. Не отказ, а недостающая часть пользовательской
цепочки: после заказа фильм или сезон пропадал из виду, и узнать, что с ним
происходит, можно было только по логам bridge, очереди и истории Radarr,
логам Prowlarr и файлам внутри контейнера — пять мест на один вопрос «где
мой фильм». Задача изложена в
`docs/superpowers/specs/2026-08-03-order-traceability-design.md`.

- [x] `bridge/app/status.py` — чистые функции без ввода-вывода:
      `movie_status()` (девять состояний), `_season_status()`/`series_status()`
      (десять состояний сезона, сведение в состояние сериала по приоритету
      `_SERIES_PRIORITY`). Порядок проверок внутри каждой функции закреплён
      тестами — это и есть контракт, а не побочный эффект реализации
- [x] `bridge/app/radarr.py`, `bridge/app/sonarr.py` — чтение `/queue`,
      `/command`, `/episode` добавлено рядом с уже существующими методами,
      новых ключей и связей между компонентами не появилось
- [x] `bridge/app/main.py` — эндпоинт `GET /status`: отказ Radarr/Sonarr
      всплывает как HTTP-ошибка через существующий `bridge_error_handler`,
      `not_ordered` при недоступном upstream не выдумывается. Запросы к
      `queue()`/`commands()`/`episodes()` выполняются только когда объект
      найден — открытие карточки незаказанного фильма не делает лишних
      обращений к сети
- [x] `bridge/static/plugin.js` — `fetchStatus()` при открытии карточки;
      текст кнопки заменяется на `label` из ответа `/status` **при любом
      успешном ответе**, независимо от `can_order` (например, у `waiting`
      кнопка покажет «Заказан, поиск ещё не запускался», хотя заказать
      повторно всё ещё можно). `can_order` решает не текст, а что делает
      нажатие: `false` — открывается экран с `label`/`detail` и пунктом
      «Обновить», перечитывающим статус без выхода из карточки; `true` —
      нажатие ведёт в обычный поток заказа. Элемент кнопки передаётся по
      цепочке вызовов явно, а не ищется глобальным селектором — Lampa как
      SPA держит в DOM карточки, с которых уже ушли, и `$('.view--order')`
      мог бы переписать состояние чужой невидимой кнопки
- [x] `checks/09-status.sh` — воспроизводит и восстанавливает
      `monitoring_broken` на живом стенде, `trap` на `EXIT` проверен боевым
      `kill -TERM` в окне между поломкой и восстановлением; добавлена в
      `checks/run-all.sh`
- [x] `checks/run-all.sh` перестал переходить в свой каталог — иначе
      `docker compose` резолвил собственный `docker-compose.yml` репозитория
      вместо развёрнутого стенда, и `03`/`08` молча превращались в ложные
      нули. Теперь проверки вызываются по абсолютному пути, рабочий каталог
      остаётся тем, откуда вызван `run-all.sh`
- [x] `pytest` в `bridge/tests/` — **114 тестов**, зелёные
- [x] `CLAUDE.md`, `docs/SPEC.md`, `docs/ACCEPTANCE.md` — контракт `/status`,
      обе таблицы состояний, приоритет сведения сезонов, критерии `09`
- [x] Отчёт `reports/stage-9-traceability.md`

**Проверено на живом стенде:** `checks/run-all.sh` целиком зелёный —
`01`, `02`, `03`, `04`, `08`, `09`; `/status` отдаёт `in_library` для
скачанного фильма (`tmdbId=399106`) и `waiting` для заказанного, но ещё не
искавшегося сезона 2 сериала Silo (`tmdbId=125988`).

**Найдено на код-ревью и исправлено дважды за этап.** Первая реализация
различала состояние импорта префиксом строки
(`trackedDownloadState.startswith("import")`). Значение `importBlocked`
тоже начинается на `import`, но означает противоположное активной загрузке:
импорт заблокирован и сам не продолжится. Префиксная проверка отдала бы
такой файл как обнадёживающее «Импортируется». Исправлено на точное
сравнение с enum (`importBlocked` → `stuck`, `importPending`/`importing` →
`importing`) — сначала для фильма, затем то же самое префиксное сравнение
обнаружилось скопированным в логику сезона и было исправлено там же.
Подробности — `docs/SPEC.md`, раздел `GET /status`.

**Известное ограничение плагина, оставлено как есть.** Если карточку
закрыть раньше, чем придёт ответ `/status`, ответ придёт в уже отсоединённый
от документа DOM. На экране это не проявляется, а чинить было бы через
`AbortController`, который недоступен в старых webview телевизоров.

# 1. Архитектура

## 1.1 Задача

Заменяемый ручной процесс: найти раздачу в браузере → указать каталог в
торрент-клиенте → переименовать файлы руками → запустить рескан библиотеки.

Целевой: открыть каталог на телефоне → нажать «заказать» → через несколько
минут файл в библиотеке с каноничным именем.

## 1.2 Компоненты и порты

| Компонент | Порт | Образ / источник |
|---|---|---|
| Kodi | 8080 | нативно на хосте, вне compose, **вне скоупа** |
| qBittorrent | 8081 | `lscr.io/linuxserver/qbittorrent` |
| Prowlarr | 9696 | `lscr.io/linuxserver/prowlarr` |
| Radarr | 7878 | `lscr.io/linuxserver/radarr` |
| Sonarr | 8989 | `lscr.io/linuxserver/sonarr` |
| bridge | 8000 | собирается из `bridge/` |
| Lampac | 9118 | `immisterio/lampac`, опционально |

Порт qBittorrent переназначен с 8080 на 8081: по умолчанию и у него, и у
Kodi веб-интерфейс на 8080, на одной машине конфликт.

## 1.3 Поток заказа

```
Телефон → Lampac → TMDB                    каталог, постеры
plugin.js → bridge                         POST {tmdb_id, type, season}
bridge → TMDB                              external_ids (только для сериалов)
bridge → Radarr | Sonarr                   добавить + запустить поиск
Radarr/Sonarr → Prowlarr → трекеры         поиск релизов
Radarr/Sonarr → qBittorrent                магнет + категория
qBittorrent → /data/torrents/…             загрузка
Radarr/Sonarr                              ЖЁСТКАЯ ССЫЛКА в /data/media/…
                                           + каноничное имя
Radarr/Sonarr → Kodi (вне скоупа)          скан библиотеки
```

**Push-вызовов только два:** plugin.js → bridge и *arr → Kodi. Остальное —
поллинг: Radarr и Sonarr сами периодически опрашивают qBittorrent. Задержка
1–2 минуты между нажатием и появлением торрента в клиенте — нормальное
поведение, не поломка.

## 1.4 Направление вызовов Prowlarr ↔ *arr

Два разговора в противоположных направлениях:

- **При настройке:** Prowlarr **пишет** индексаторы в Radarr и Sonarr через
  их API. Настраивается в Prowlarr → Settings → Apps: адрес и API-ключ
  каждого приложения. Режимы синхронизации — «Add and Remove Only» и
  «Full Sync». Индексаторы синхронизируются по поддерживаемым категориям:
  TV-индексаторы уходят только в Sonarr, и наоборот.
- **При поиске:** Radarr и Sonarr **обращаются** к Prowlarr по Torznab.

Следствие: раздел Indexers в Radarr и Sonarr заполняется сам. Руками там
ничего не создаётся.

## 1.5 Второй поток (вне скоупа)

```
Телефон → Lampac → парсер → трекеры → TorrServer → просмотр
```

Одноразовый просмотр без скачивания. Библиотеку не трогает. Упомянут,
чтобы не пытаться его интегрировать.

## 1.6 Раскладка файловой системы

```
${DATA_ROOT}
├── torrents
│   ├── movies          категория qBittorrent "radarr"
│   └── tv              категория qBittorrent "sonarr"
└── media
    ├── movies          root folder Radarr
    ├── tv              root folder Sonarr
    ├── _test_movies    тестовый root folder, выбрасывается
    └── _test_tv        тестовый root folder, выбрасывается
```

**Все контейнеры получают одно монтирование: `${DATA_ROOT}:/data`.**

`DATA_ROOT` находится **вне репозитория**. Если положить его внутрь, он
окажется на той же ФС, что и остальное, и проверка жёстких ссылок перестанет
быть осмысленной.

## 1.7 Почему жёсткие ссылки, а не перемещение

Файл нужен одновременно в двух местах: в торрент-каталоге под релизным
именем — чтобы qBittorrent продолжал раздавать; в библиотеке под каноничным —
чтобы его распознал скрапер.

`mv` уносит файл из торрент-каталога, qBittorrent теряет его, раздача
отваливается. Копирование решает это ценой двойного места.

Жёсткая ссылка — второе имя для того же inode. Данные на диске одни, имён
два, оба равноправны: удаление одного не затрагивает другое, блоки
освобождаются только с исчезновением последней ссылки. Досидировал →
qBittorrent удалил свою запись по правилу рейтинга → файл в библиотеке цел,
место не тронуто.

Второй эффект — атомарность. Внутри одной ФС импорт это `rename`: мгновенно
и неделимо. Через границу ФС это копирование с удалением: долго, двойной
I/O, и всё это время в библиотеке лежит недокопированный файл.

Ограничение: номер inode осмыслен только внутри своей ФС, между разными
файловыми системами жёсткую ссылку создать нельзя. Отсюда правило про
единственное монтирование. Также: между сабволюмами btrfs жёсткие ссылки
не работают; на ext4 в одном разделе работают.

**Настройка называется «Use Hardlinks instead of Copy», и когда ссылка
невозможна, *arr молча копирует. Ошибки нет.** Поэтому проверка через
`stat -c %h`, а не «файл появился». Отдельно: `du` считает такие данные
дважды, правду говорит `df`.

# 2. bridge — спецификация

## 2.1 Назначение

Принять от плагина TMDB-идентификатор и превратить в корректный вызов
Radarr или Sonarr.

Существует потому, что:

- Sonarr работает по TVDB, карточка Lampa — по TMDB, нужна трансляция;
- добавление одного сезона требует нескольких вызовов;
- API-ключи не должны попадать в браузерную страницу;
- плагин и API на одном origin — вопрос CORS снимается.

## 2.2 Требование отсутствия состояния

Ни базы, ни очереди, ни повторов, ни фонового опроса статусов.
Принял → транслировал → переслал → ответил.

Обоснование: надёжная доставка уже реализована в Radarr и Sonarr.
Дублирование превращает мост во второй Radarr.

## 2.3 Контракт

### `POST /order`

```json
{ "tmdb_id": 10378, "type": "movie", "season": null }
```

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `tmdb_id` | int | да | Идентификатор TMDB из карточки Lampa |
| `type` | `"movie"` \| `"tv"` | да | Тип контента |
| `season` | int \| null | для `tv` — да | Номер сезона |

Успех — `200`:

```json
{ "status": "queued", "title": "Big Buck Bunny", "detail": null }
```

Уже в библиотеке — тоже `200`:

```json
{ "status": "exists", "title": "Big Buck Bunny", "detail": "уже в библиотеке" }
```

Ошибка — `4xx` / `5xx`:

```json
{ "status": "error", "title": null, "detail": "у сериала нет tvdb_id в TMDB" }
```

`detail` показывается пользователю в Lampa как есть: человекочитаемо,
по-русски.

### `GET /plugin.js`

Отдаёт файл плагина.

- `Content-Type: application/javascript`
- при `BRIDGE_ENV=dev` — `Cache-Control: no-store`

Lampa кеширует файлы плагинов. Без `no-store` при разработке будет
исполняться старая версия — типовая потеря времени.

### `GET /health`

`200`, пустое тело.

## 2.4 Обработка фильма

1. Разрешить `qualityProfileId` по имени: `GET /api/v3/qualityprofile`
2. Разрешить `rootFolderPath`: `GET /api/v3/rootfolder`
3. `POST /api/v3/movie`

Поля запроса — `tmdbId`, `qualityProfileId`, `rootFolderPath`, `monitored`,
`minimumAvailability`, `addOptions.searchForMovie`. **Точный состав и типы
сверить с `openapi/radarr-v3-*.json`.**

`minimumAvailability` задаётся из `RADARR_MIN_AVAILABILITY`. Допустимые
значения: `announced`, `inCinemas`, `released`, `preDB`. По умолчанию
`released`. `preDB` сейчас идентичен `released`, использовать его смысла нет.

**Слишком строгое значение — классическая причина «добавилось, но не ищет»:**
Radarr считает, что фильм ещё не вышел, добавление проходит, поиск не
стартует, ошибки нет.

В dev-режиме `searchForMovie` — всегда `false`.

## 2.5 Обработка сезона сериала

1. `GET https://api.themoviedb.org/3/tv/{tmdb_id}/external_ids` → `tvdb_id`.
   Отсутствует или пуст → внятная ошибка `4xx`, не `500`. У части
   регионального контента его действительно нет.
2. Разрешить `qualityProfileId` и `rootFolderPath` в Sonarr.
3. `POST /api/v3/series` с `tvdbId`, `addOptions.monitor: "none"` и
   **`monitorNewItems: "none"`**.
4. Включить мониторинг нужного сезона: `POST /api/v3/seasonpass` с массивом
   `series`, где для целевого сериала `seasons` содержит
   `{seasonNumber, monitored}` — целевой `true`, остальные `false`.
5. Запустить поиск: `POST /api/v3/command` с
   `{"name": "SeasonSearch", "seriesId": …, "seasonNumber": …}`.

**`monitorNewItems: "none"` обязателен.** Это API-форма настройки
«Monitor New Seasons». Без неё Sonarr начнёт мониторить будущие сезоны, и
заказ одного сезона превратится в подписку на сериал. Глобального значения
по умолчанию для этого поля нет, задаётся только на сериал.

Массив `seasons` можно передать и прямо в POST на шаге 3, но `addOptions.monitor`
может переопределить флаги на момент добавления. Поэтому надёжнее два шага:
добавить с `monitor: "none"`, затем `seasonpass`.

**Поиск по названию через `series/lookup?term=` не использовать** — нечёткое
совпадение притащит не тот сериал. Только точный `tvdbId`. Дополнительно:
`series/lookup` возвращает недостоверные флаги `monitored` для ещё не
добавленных сериалов, полагаться на них нельзя.

Известная краевая проблема: эпизоды, дописанные позже в уже отслеживаемый
текущий сезон, могут оказаться немониторимыми. Для идущих сериалов
проверить поведение отдельно.

## 2.6 Конфигурация

Только через переменные окружения, ни одного значения в коде. Полный список —
в `.env.example`. Адреса *arr — по именам сервисов внутри compose-сети
(`http://radarr:7878`), не по IP.

`.env` в `.gitignore`, `.env.example` в репозитории — оба созданы **до
первой строки кода**.

## 2.7 Логирование

Каждый входящий запрос пишется целиком: тело, результат трансляции ID,
исходящий вызов, ответ *arr.

Это основной инструмент отладки плагина: тыкаешь в интерфейсе Lampa,
смотришь логи bridge, видишь, что реально пришло. Быстрее любых тестов на JS.

## 2.8 CORS

Плагин отдаётся с того же origin, что и API, поэтому в production CORS не
нужен. В dev, когда Lampa поднята на `localhost:3000`, — `CORSMiddleware`
с явным списком origin. **Не `*`.**

Для сравнения: у Radarr и Sonarr настроек CORS нет вообще — именно поэтому
плагин обращается к bridge, а не к ним напрямую.

# 3. plugin.js — спецификация

## 3.1 Поведение

1. Добавить в карточку кнопку «Заказать»
2. Дождаться готовности `tmdb_id` и типа контента
3. Для сериала — показать выбор сезона
4. Один `POST` на `/order`
5. Показать уведомление с текстом из `detail`

Ни ретраев, ни хранения, ни опроса статуса, ни знания об *arr.

## 3.2 Асинхронное разрешение идентификатора

**Идентификаторы в карточке Lampa разрешаются не сразу**, особенно когда
основной источник — TMDB, а не CUB. Читать сразу при открытии карточки
нельзя: нужно дождаться полной загрузки данных карточки.

Конкретный механизм — какое событие слушать, где лежит тип контента —
уточнить по локально собранной документации и рабочему примеру, см.
`OPEN-QUESTIONS.md`. Рабочий основной источник — TMDB; CUB не поддерживается.

## 3.3 Секреты

В плагине только адрес bridge. Ни ключей, ни токенов, ни адресов *arr.
Код исполняется в браузерной странице; если Lampa открыта не со своего
хоста, всё её содержимое доступно чужой странице.

## 3.4 Отладка

Разработка на десктопе: `npm run start` в `yumata/lampa-source`, локальная
Lampa на `http://localhost:3000`. Переустанавливать плагин на телевизоре при
каждой правке — не вариант.

Установка для проверки на устройстве: Настройки (шестерёнка) → Расширения →
добавить плагин → адрес.

Lampa открыта под лицензией ISC (по `package.json` в `lampa-source`).

# 4. Инфраструктура

## 4.1 Обязательные параметры контейнеров

Одинаково во всех сервисах: `PUID`, `PGID`, `UMASK=002`, `TZ`, монтирование
`${DATA_ROOT}:/data`, конфиг в `./config/<service>:/config`.

Расхождение `PUID`/`PGID` между сервисами — вторая по частоте поломка после
индексаторов: qBittorrent пишет от одного uid, *arr не может переместить
файл. Проявляется как молчаливые ошибки импорта.

Переменная называется `UMASK`. `UMASK_SET` в образах linuxserver.io признана
устаревшей.

## 4.2 Фиксация версий

Теги пинуются через `.env` на конкретные версии. Никаких `latest`,
автообновление не настраивается: миграции БД у *arr односторонние, откат
после запуска новой версии невозможен.

## 4.3 qBittorrent

- Категория `radarr` → `/data/torrents/movies`
- Категория `sonarr` → `/data/torrents/tv`
- Веб-интерфейс на 8081
- Временный пароль при первом запуске пишется в лог контейнера
- Остановка раздачи по рейтингу или времени — на вкус

## 4.4 Radarr и Sonarr

- Download Client: qBittorrent с соответствующей категорией
- Root folders: из `.env`
- **Use Hardlinks instead of Copy — включено**
- **Metadata: все writer'ы выключены**
- Схема переименования — из `NAMING.md`
- Sonarr: `monitorNewItems: "none"` на каждом добавляемом сериале
- Connect → уведомления на **Health Issue** в Telegram или ntfy

Последнее экономит больше всего времени при эксплуатации: страница здоровья
ловит почти всю поломку индексаторов, прав и клиента загрузки.

## 4.5 Prowlarr

- Индексаторы с логинами для приватных — **добавляются последними, человеком**
- Settings → Apps: Radarr и Sonarr с внутренними адресами и ключами
- FlareSolverr — только если конкретный трекер требует

## 4.6 Kodi — вне скоупа

Фиксируется заранее, чтобы потом не переименовывать библиотеку:

- источники `/data/media/movies` и `/data/media/tv`
- скраперы Kodi включены, NFO от *arr не используются
- схема имён — `NAMING.md`

Что понадобится при подключении: Настройки → Службы → Управление →
Разрешить управление по HTTP, порт 8080, логин и пароль, SSL не включать.
Затем в Radarr/Sonarr → Settings → Connect → Kodi.

Актуальная версия JSON-RPC API — v13; текущий стабильный Kodi — v21.3
«Omega» (октябрь 2025).

**Известная проблема:** `VideoLibrary.Scan` с параметром `directory` для
сериалов **сломан начиная с Kodi v21 Omega** (issue #26169): Kodi
сопоставляет подкаталоги сезонов вместо переданного пути. Для фильмов
работает. Вывод — использовать полный скан без параметра, либо
directory-скан только для фильмов. Встроенный коннектор *arr дёргает те же
методы и наследует то же ограничение.

# 5. Тестовый стенд

Реальные трекеры на этапах 1–5 не подключаются: раздача — самое
недетерминированное звено, а приватные трекеры банят за поток запросов.

Вместо этого — локальный торрент из открытой короткометражки. Требования к
материалу:

- **существует в TMDB**, иначе Radarr не сопоставит
- открытая лицензия
- настоящий видеофайл: у него есть длительность, кодек, разрешение, поэтому
  MediaInfo и определение качества у *arr работают честно. Файл-пустышка
  может быть отброшен как sample

Кандидаты: открытые ленты Blender (Big Buck Bunny, Sintel, Tears of Steel,
Cosmos Laundromat) под CC-BY; из общественного достояния — Steamboat Willie.

Порядок: скачать → назвать по релизной конвенции → сделать торрент →
положить данные на место → добавить в qBittorrent в нужную категорию.
Торрент сразу 100% и сидирует, сеть не нужна.

Для Sonarr: сериалов с открытой лицензией и записью в TVDB практически нет.
Практичный обход — взять `tvdb_id` реального сериала, а файлом положить ту же
короткометражку, переименованную в `SxxEyy`. Sonarr сопоставляет по имени,
не по содержимому, поэтому импорт проверяется честно. Держать в
выбрасываемом тестовом root folder.

# 6. Что будет ломаться при эксплуатации

По убыванию вероятности:

1. **Индексаторы.** Раз в месяц, а не раз в год: смена домена, Cloudflare,
   истёкшая сессия приватного трекера. FlareSolverr сам хрупкий.
2. **Плагин Lampa.** Обновилась Lampa — поехали внутренности. Поэтому тонкий.
3. **Балансеры Lampa** (второй поток). Чужие скраперы чужих сайтов.
   Библиотеку не задевают.
4. **Дрейф метаданных TVDB.** Переименовали сериал, перенумеровали сезоны —
   Sonarr перестаёт сопоставлять. Редко, выглядит страшно.
5. **Права.** Расхождение `PUID`/`PGID`, молчаливые ошибки импорта.
6. **Миграции БД при обновлении *arr.** Редко, необратимо.
7. **Место на диске.** Жёсткие ссылки экономят, но раздача и библиотека на
   одном диске.

Самый стабильный элемент — bridge: говорит с зафиксированными REST API по
документированным полям.

# CLAUDE.md

Домашний медиа-стек. Заказ фильма или сезона сериала с телефона →
автоматическая загрузка, переименование, готовая библиотека.

Этот файл — инварианты и запреты. Читается всегда, поэтому короткий.

- Детали: `docs/SPEC.md`
- Процесс, этапы, стоп-условия: `docs/PROCESS.md`
- Критерии приёмки: `docs/ACCEPTANCE.md`
- Непроверенные допущения: `docs/OPEN-QUESTIONS.md`
- **Что уже сделано и что осталось: `docs/CHECKLIST.md`** — читать вторым
  после этого файла, чтобы не переделывать сделанное и не считать сделанным
  недоказанное

---

## Область работ

**В скоупе:** инфраструктура, конфигурация *arr через API, bridge, плагин
Lampa, тестовый стенд, проверки.

**Вне скоупа:** интеграция с Kodi. Коннектор добавляется позже галочкой в
конфигурации, кода не требует.

Схема именования файлов при этом фиксируется **сейчас** (`docs/NAMING.md`),
иначе при подключении Kodi придётся переименовывать всю библиотеку.

**Терминальная проверка минимального конвейера:** файл лежит по ожидаемому
пути, с ожидаемым именем, и является жёсткой ссылкой. Не «появилось в Kodi».

## Что пишем сами

1. `docker-compose.yml` — инфраструктура из готовых образов
2. `provision/` — конфигурация *arr скриптами через их API
3. `bridge/` — HTTP-эндпоинт на Python, мост между Lampa и *arr
4. `bridge/static/plugin.js` — плагин к Lampa, тонкий
5. `checks/` — проверки приёмки
6. `fixtures/` — тестовый стенд
7. `lampac/init.conf` — конфигурация Lampac

Всё остальное — готовый софт, который только конфигурируется.

Седьмой пункт держится в git, а не в `config/`, потому что это декларативная
настройка, а не состояние сервиса. Без него Lampac вяжется на `127.0.0.1`
внутри контейнера и снаружи недоступен — при том что healthcheck образа
показывает `healthy`.

## Роли компонентов

| Компонент | Единственная задача |
|---|---|
| Lampa | Витрина: листать каталог, нажать «заказать» |
| Lampac | Бэкенд Lampa: TMDB-прокси, раздача фронтенда |
| **bridge** | Трансляция ID, разбор сезонов, справочник профилей, текущее состояние заказа, вызов *arr |
| Prowlarr | Реестр трекеров. Ничего не решает, только ищет |
| Radarr | Выбирает релиз фильма, импортирует, переименовывает |
| Sonarr | То же для сериалов + сопоставление эпизодов |
| qBittorrent | Качает в каталог по категории |
| Kodi | Библиотека, скрапинг, воспроизведение (вне скоупа) |

## Решения, которые не пересматриваются

Каждое обсуждалось и принято. Не предлагай альтернативы, даже если в отрыве
от контекста они выглядят разумнее.

- **Метаданные пишет только Kodi.** Writer'ы NFO в Radarr и Sonarr выключены.
  Их NFO — известный способ испортить базу Kodi.
- **Индексаторы только через Prowlarr.** Никогда не создавать индексаторы
  вручную в Radarr или Sonarr: Prowlarr пишет их туда сам через Apps.
- **Ключи API только в bridge.** В `plugin.js` не попадает ни один секрет,
  только адрес bridge.
- **Плагин остаётся тонким.** Прочитал id, спросил сезон и качество, отправил
  один заказ, показал уведомление, показал состояние, полученное от bridge.
  Логика — в Python, включая формулировки состояний: своей логики состояний
  плагин не содержит, он показывает готовый текст. Список профилей качества
  плагин не знает, а забирает у bridge: переименованный в Radarr профиль иначе
  сломал бы заказ, и молча.
- **Единственное монтирование `/data`** во все контейнеры. Не раздельные
  `/downloads` и `/movies`.
- **bridge без состояния.** Ни базы, ни очереди, ни повторов, ни трекинга
  статусов. Не получилось — вернул ошибку, человек нажал ещё раз.
- **Теги образов зафиксированы** через `.env`. Никаких `latest`,
  никакого автообновления: миграции БД у *arr односторонние.
- **Не добавляем** Jellyfin, Jellyseerr, FileFlows, Bazarr, MariaDB,
  FileBot, tinyMediaManager. Рассмотрены и отвергнуты.

## ЗАПРЕЩЁННЫЕ ПОДМЕНЫ

Главное правило файла. Если перечисленное слева не работает — **останавливайся
и пиши отчёт**. Не делай то, что справа. Каждая подмена выглядит разумным
инженерным решением и молча ломает замысел.

| Не получилось | НЕ ДЕЛАТЬ ВМЕСТО |
|---|---|
| Массив `seasons` в POST Sonarr | Мониторить сериал целиком |
| Мониторинг эпизодов заказанного сезона | Ограничиться флагом сезона |
| Путь по категории qBittorrent | Выключить ATM: категория станет меткой |
| Трансляция TMDB→TVDB | Искать по названию в Sonarr (`series/lookup?term=`) |
| Жёсткая ссылка | Копировать или `mv` |
| Одно монтирование `/data` | Раздельные монтирования |
| Явный список origin в CORS | `Access-Control-Allow-Origin: *` |
| Индексатор через Prowlarr Apps | Создавать индексатор в Radarr вручную |
| Поле не найдено в схеме | Подставить имя «по смыслу» |
| Ключ из окружения | Хардкод в коде или в тесте |
| `monitorNewItems: "none"` | Оставить значение по умолчанию |
| Импорт не сработал | Переместить файл скриптом руками |

Правило шире таблицы: **если обход требует отступить от инварианта —
это стоп, а не решение.**

## Проверять результат, а не намерение

**Утверждение приёмки формулируется о наблюдаемом результате.** «Настройка
принята» и «настройка действует» — разные утверждения, и расходятся они
молча.

Случаи, которые уже стоили работающего конвейера:

| Проверялось | А надо было |
|---|---|
| отслеживаемые сезоны | отслеживаемые ЭПИЗОДЫ — по ним планируется загрузка |
| заведённые категории qBittorrent | фактический путь скачанного файла |
| `202 Accepted` от seasonpass | состояние, прочитанное отдельным `GET` |
| `pgrep dotnet` в healthcheck Lampac | сервис отвечает по HTTP |
| ответ `POST /series` (`monitored: true`) | то, что легло в базу (`false`) |
| пустая история Radarr | отсутствие событий `grabbed` |

Признак ошибки один и тот же: проверка утверждает то, что мы ОТПРАВИЛИ или
НАСТРОИЛИ, вместо того, что получилось. Такая проверка зелёная на сломанном
стеке.

Отсюда же — читать результат обратно после каждой записи, у которой ответ
приходит раньше применения.

## Источник истины по API

**Имена полей берутся из схем в `openapi/`. Не из памяти.**

Схемы **не отдаются** живым инстансом по `/api/v3/openapi.json` — на
production-сборках этого пути нет, Swagger UI поднимается только в
debug-режиме. Схемы лежат в исходниках проектов:

- Radarr: `src/Radarr.Api.V3/openapi.json`
- Sonarr: аналогичный путь в его репозитории

Порядок: `scripts/fetch-openapi.sh` качает схему, записывает в `openapi/`
и фиксирует в `openapi/SOURCES.md` версию и коммит. Затем
`scripts/check-versions.sh` сверяет её с версией живого инстанса из
`/api/v3/system/status`.

**Расхождение версий — стоп-условие.** Схема из main-ветки и контейнер
полугодовой давности это разные схемы, и расхождение молчаливое.

## Безопасность при разработке

**Трекеры на этапах 1–5 не подключаются.** Индексаторов нет, поиск в
интернете не выполняется. Причины: раздача — самое недетерминированное звено
цепочки, а приватные трекеры банят за поток запросов из отладочного цикла.

Проверка конвейера идёт на локальном торренте из `fixtures/` — открытая
короткометражка, существующая в TMDB. Раздача создаётся локально и сразу
100%, сеть не нужна.

**`BRIDGE_ENV=dev` → поиск не запускается никогда.** Параметры
`searchForMovie` и аналоги передаются как `false`. Реальная загрузка
вызывается только человеком, вручную.

Заказы в dev-режиме помечаются тегом из `TEST_TAG`. Отдельного root folder
для них нет — он был убран как лишняя сущность: тега достаточно, чтобы
отличить отладочные заказы и снести их одной командой.

## Чего агент не угадает

**Про Lampa в обучающих данных почти ничего** — нишевый русскоязычный
проект. Не выдумывай API плагинов. Источники:

- документация собирается локально: `npm run doc` в `yumata/lampa-source`,
  результат в `build/doc/index.html`
- рабочий пример с исходниками: `and7ey/lampa`

Идентификаторы в карточке Lampa разрешаются **асинхронно**. Читать сразу
при открытии карточки нельзя.

Отладка плагина — через логи bridge: он пишет каждый входящий запрос,
ты тыкаешь в интерфейсе и смотришь, что пришло.

## Процесс

Полностью — в `docs/PROCESS.md`. Кратко:

- восемь этапов, строго последовательно
- ветка на этап: `stage/1-infra` … `stage/8-monitoring-and-paths`, цепочкой
- этап не считается закрытым, пока не прошли его проверки из `checks/`
- **пуш только в ветку.** `main` мержит человек, `deploy.sh` тянет `main`
- перед каждым этапом — снапшот ВМ
- при срабатывании стоп-условия — отчёт в `reports/`, работа прекращается
